# Forge 1.0 Roadmap — Confidence-Ladder Plan

> **For Hermes:** Execute this plan phase-by-phase. Each phase ends with a verification step and a commit; do not proceed to the next phase without user confirmation.

**Goal:** Take Forge from `0.1.0a1` (feature-complete alpha) to a well-earned `v1.0.0` — driven by *evidence of stability*, not by roadmap completion.

**Architecture:** Version number tracks confidence, not features. Each release step has an explicit trigger (proof conforming, N external users, API-freeze window). Proofs are the evidence engine; PyPI + CI are the delivery rails; user outreach is the validation loop.

**Tech Stack:** Python 3.10–3.12, three distributions (`forge-foundation`, `forge-planner`, `forge-mcp-base`), GitHub Actions CI, proofs/ standard (`proof-spec-0.1`), pip + uv, PyPI.

```
0.1.0a1   Alpha        — "Does the architecture work?"            (on PyPI)
0.1.0a2   Proof #2            — CHIP-8 conforming (done, live)
0.1.0a3   Generalization      — C++ + Rust proofs (language)   [next]

0.1.0b1   External validation — 5 independent users AND 3 completed projects
0.1.0rc1  API freeze          — public surface frozen; ≥1 external PR merged
1.0.0     Stable              — no API changes 2–3 months + all gates green
```

**Decision (Aug 2026):** the C++/Rust/multi-agent proofs share one Generalization-NARRATIVE,
but releases stay SPLIT — C+++Rust ship as `a3` together, the slower/riskier multi-agent
is its own `a4`. Do not gate the fast language proofs on the 100+ task run.
**Beta redefinition:** 5 *independent* users (no 1:1 author coaching) **AND** 3
*completed* projects (a finished artifact derived by their own use, committed by
them), per ROAD_TO_1.0.md.

## Risks & open questions

- **C++/Rust toolchains in CI**: need to add compiler/rustup setup to the actions workflow — small, but new surface
- **Outreach ROI**: 5 external users is the least-controllable gate; fallback is narrowing scope (e.g. 3 users) if the project stays niche — *flag to user before lowering the bar*
- **Multi-agent proof cost**: 100+ task run is the longest/ most expensive proof (CHIP-8 took 44 min); schedule it as a dedicated session
- **a2 → a3 → a4 churn**: publishing an alpha per proof is cheap on PyPI but noisy; could batch a3+a4 if the two non-Python proofs land close together — *user's call at Phase 1 end*
- **Open question for user:** keep the version ladder strictly tied to evidence (ChatGPT's model), or cut stable `1.0.0` on a fixed date once rc is out? Recommendation: evidence-based, per ChatGPT.
